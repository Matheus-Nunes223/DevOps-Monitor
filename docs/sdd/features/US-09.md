# US-09 · Gerador de Carga e Falhas

- **Épico:** Demonstração
- **Prioridade / pontos:** Alta · 3
- **Requisito:** RF-14 e cenários de demonstração das US-13 a US-18
- **Depende de:** US-01 (ambiente Compose), US-04 a US-08 (sondas)

## História
Como avaliador/operador, quero executar cenários reproduzíveis de tráfego e falhas no laboratório para observar métricas, alertas e recuperação.

## Cenários exigidos
- `normal`: tráfego HTTP leve e constante.
- `spike`: pico limitado de requisições concorrentes.
- `bruteforce`: POSTs inválidos ao fixture `/login` com usuário sintético.
- `stop_service`: parar um serviço permitido do Compose por período limitado e restaurá-lo.
- `edit_config`: alterar temporariamente uma diretiva Nginx válida, validar/recarregar e restaurar os bytes originais mesmo em erro.
- `smtp_flood`: enviar um volume limitado de mensagens para MailHog pelo Postfix.

## Segurança e limites
- Uma CLI única com limites máximos de quantidade, concorrência, duração e taxa.
- `stop_service`, `edit_config` e `smtp_flood` exigem `--confirm-fault`; não executar esses cenários implicitamente.
- O target HTTP deve ser loopback/local por padrão; alvo externo exige opt-in explícito.
- `stop_service` só pode escolher serviços monitorados, verifica estado inicial e preserva se estava rodando.
- `edit_config` só altera `infra/nginx/nginx.conf`, faz backup em memória e restaura em `finally`; não altera arquivos fora do laboratório.
- Não registrar senhas, corpo de e-mail nem credenciais; brute force usa usuário sintético.

## Critérios de aceite
- Cada cenário é invocável pela mesma CLI e retorna falha não-zero se uma operação necessária falhar.
- Os cenários de falha têm limpeza/restauração garantida.
- Testes usam adapters falsos/tempfile; não param serviços nem enviam carga real durante a suíte.
