# US-08 · Métricas SMTP

- **Épico:** Coleta
- **Prioridade / pontos:** Alta · 5
- **Requisito:** RF-05
- **Depende de:** US-01 (Postfix/MailHog), US-03 (coletor) e US-04 (SMTP disponível)

## História
Como operador, quero acompanhar fila, entrega, rejeições, timeouts e latência de ponta a ponta para detectar problemas no relay SMTP.

## Critérios de aceite
- Parsear logs Postfix para resultados sent/deferred/bounced, rejeições, timeouts e mensagens aceitas no período.
- Parsear `postqueue -j` como JSON Lines e contar mensagens pendentes, inclusive fila vazia.
- Gerar uma mensagem sonda com identificador único pelo Postfix e medir até aparecer na API MailHog.
- Isolar coleta de logs, fila e e-mail sonda em probes distintas.
- Excluir a própria mensagem sonda dos contadores de volume e entrega.
- Nunca registrar endereço de e-mail, corpo da mensagem, identificador de fila ou token da sonda.

## Segurança e integração
- O coletor lê logs do container Postfix por uma rota de logs restrita do proxy Docker.
- Para a fila, o proxy executa apenas `postqueue -j` com parâmetros fixos no container Postfix; não expõe uma API de exec genérica.
- MailHog é acessado somente pela rede interna. A API é usada para pesquisar a sonda pelo token no conteúdo.
- Testes unitários usam fixtures e adapters falsos; execução com Postfix/MailHog reais ainda é necessária.
