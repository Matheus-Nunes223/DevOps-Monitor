# US-01 · Ambiente monitorado

- **Épico:** Infra
- **Prioridade / pontos:** Alta · 5
- **Requisitos da spec geral:** ambiente reproduzível, observabilidade do Nginx e serviços-base
- **Depende de:** Sprint 0 (repositório e ferramentas)

## História
Como pessoa que demonstra o DevOps Monitor, quero iniciar serviços locais representativos com um único `docker compose up` para que o coletor e as demonstrações posteriores possam medir sistemas reais.

## Critérios de aceite
```gherkin
Cenário: ambiente saudável
  Dado Docker Compose v2 e as imagens disponíveis
  Quando inicio a composição
  Então Nginx/app, PostgreSQL, CoreDNS, Postfix e MailHog ficam saudáveis em até 60 segundos

Cenário: tráfego web e tentativa de login
  Dado o ambiente em execução
  Quando consulto / e envio POST /login
  Então / retorna a página demo, login inválido retorna 401 e registra o usuário tentado no access log JSON

Cenário: isolamento de rede
  Dado os serviços em execução
  Então apenas portas de demonstração necessárias ficam publicadas no loopback e banco/SMTP permanecem internos
```

## Casos de borda
- [ ] Dependência indisponível impede a prontidão e fica visível no healthcheck.
- [ ] Usuário de login com caracteres especiais é escapado no JSON de log.
- [ ] Dados vazios/ausentes não são apresentados como métricas medidas.

## Fora do escopo desta história
- Coletor, métricas persistidas, alertas e painel; esses pertencem a histórias posteriores.
- Autenticação real: `/login` é apenas fixture não autenticadora para ensaios de segurança.

## Dados e contratos afetados
- Serviço web em `infra/demo-app`; logs Nginx JSON compartilhados em volume.
- PostgreSQL 16 com `pg_stat_statements`; CoreDNS zona `lab.local` e endpoint Prometheus; Postfix relay para MailHog.
- Sem tabelas, métricas persistidas ou telas.

## Segurança
- Entradas não confiáveis: corpo de login e cabeçalhos HTTP; validar/parsing limitado e escapar saída.
- Segredos: nenhum. Credenciais de desenvolvimento do Postgres são explícitas e não reutilizáveis fora do laboratório.
- Portas publicadas somente em `127.0.0.1`; serviços internos sem exposição ao host.
