# US-05 · Métricas Web

- **Épico:** Coleta
- **Prioridade / pontos:** Alta · 5
- **Requisitos da spec geral:** RF-02, P1, P2, P7
- **Depende de:** US-01 (access log JSON/stub_status), US-03 (modelos/runner) e US-04 (availability)

## História
Como operador, quero métricas Web calculadas a partir dos registros reais do Nginx para investigar volume, latência, erros HTTP e conexões ativas sem apresentar dados simulados.

## Critérios de aceite
```gherkin
Cenário: ciclo com requisições registradas
  Dado que o coletor leu logs JSON novos e válidos
  Quando agrega a janela desde a última leitura
  Então grava RPS, p50/p95 em milissegundos, contagens por código e taxas 4xx/5xx

Cenário: não há tráfego
  Dado que a leitura do log foi concluída sem novas linhas
  Quando calcula métricas
  Então RPS é 0, contagens ficam vazias e latências/taxas sem denominador ficam NULL

Cenário: rotação e truncamento
  Dado que o log é substituído ou truncado
  Quando o coletor lê novamente
  Então reinicia o offset e não repete linhas antigas

Cenário: falha isolada
  Dado que o arquivo de log ou stub_status está inacessível
  Quando o runner executa as probes Web
  Então registra erro, persiste valores ausentes daquela probe e mantém as demais probes
```

## Casos de borda
- [ ] Linhas JSON incompletas são retidas até chegarem ao próximo ciclo.
- [ ] Linhas malformadas são contadas em log sem registrar IP, URI ou usuário.
- [ ] Arquivo truncado com mesmo inode e arquivo substituído por rotação reiniciam corretamente.
- [ ] Sem requests, proporções e percentis são NULL; RPS zero decorre da janela efetivamente lida.

## Fora do escopo desta história
- Detecção de brute-force/DDoS (US-15/US-16), histórico de 24 h e visualização no painel.
- Interpretar `stub_status` como tráfego de usuários; ele é uma medição separada de conexões ativas.

## Dados e contratos afetados
- Log de entrada: JSON do Nginx (`remote_addr`, `status`, `request_time`, `request_uri`, `request_method`, `user`).
- Métricas: `web.rps`, `web.latency_p50_ms`, `web.latency_p95_ms`, `web.status_count` com label `code`, `web.error_4xx_rate`, `web.error_5xx_rate`, `web.active_connections`.
- Persistência em `metrics`; ausência vira `NULL`, contagem por código é gravada somente para códigos observados.

## Segurança
- Log é entrada não confiável; JSON validado, sem executar ou interpolar valores em SQL.
- Linhas inválidas não são copiadas para logs do coletor (podem conter IP/URI/usuário).
- `stub_status` é consultado na rede privada; seu próprio acesso não entra no access log.

## Perguntas em aberto
- [ ] A janela RPS usa o tempo monotônico desde a última leitura; reinício do coletor começa uma janela nova e não reprocessa histórico anterior.
