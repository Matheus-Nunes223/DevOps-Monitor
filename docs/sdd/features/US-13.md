# US-13 · Motor de regras de alerta (3 níveis)

> Exemplo preenchido do template. Use como referência para as outras histórias.

- **Épico:** Alertas
- **Prioridade / pontos:** Alta · 5
- **Requisitos da spec geral:** RF-11, RF-12, RNF-02
- **Depende de:** US-02 (tabelas `alert_rules`, `alerts`, `services`), US-04 a US-07 (métricas)

## História
Como **operador**, quero que cada métrica vire um estado **Verde, Amarelo ou Vermelho** para saber na hora o que precisa de atenção.

## Critérios de aceite
```gherkin
Cenário: Degradação confirmada em 2 ciclos
  Dado a regra web.latency_p95_ms com amarelo > 500 e vermelho > 2000
  E o serviço web em Verde
  Quando dois ciclos seguidos medem 800 ms
  Então um alerta Amarelo é aberto para web com value = 800
  E services.current_level de web passa a 'yellow'

Cenário: Pico isolado não abre alerta
  Dado o serviço web em Verde
  Quando um ciclo mede 800 ms e o seguinte mede 300 ms
  Então nenhum alerta é aberto

Cenário: Escalonamento de Amarelo para Vermelho
  Dado um alerta Amarelo aberto para web.latency_p95_ms
  Quando dois ciclos seguidos medem 2500 ms
  Então o alerta Amarelo é fechado
  E um alerta Vermelho é aberto

Cenário: Recuperação
  Dado um alerta Vermelho aberto para web.latency_p95_ms
  Quando dois ciclos seguidos medem 200 ms
  Então o alerta é marcado como resolved com resolved_at preenchido
  E services.current_level de web volta a 'green' se não houver outro alerta aberto

Cenário: Métrica ausente
  Dado a sonda web falhou e gravou value = null
  Quando o motor avalia a regra
  Então o contador da regra não muda
  E nenhum alerta é aberto ou fechado por essa regra

Cenário: Reinício do coletor
  Dado um alerta Amarelo aberto antes do coletor reiniciar
  Quando o coletor sobe de novo
  Então o motor considera web em Amarelo e não abre um alerta duplicado
```

## Casos de borda
- [ ] Operador `<` (ex.: `smtp.delivery_rate < 0.95`)
- [ ] Valor exatamente no limite (500 não viola `> 500`)
- [ ] Regra desabilitada (`enabled = false`) fecha o alerta aberto dela
- [ ] Serviço com várias regras: o estado é o pior entre elas
- [ ] Alertas de segurança (`kind` ddos, bruteforce...) também contam para o pior estado

## Fora do escopo desta história
- Envio de e-mail (US-14). O motor só chama `notifier.on_open/on_close`.
- Edição de regras pelo painel.

## Dados e contratos afetados
- Lê: `alert_rules`, última linha de `metrics` por (service_id, metric) do ciclo
- Escreve: `alerts`, `services.current_level`
- Interface: `evaluate(rules, values, state) -> (new_state, transitions)` como função pura em `alerts/engine.py`

## Segurança
- Nenhuma entrada externa direta; valores vêm das sondas.
- Escrita com a conexão do coletor (service role); nada exposto ao painel.
