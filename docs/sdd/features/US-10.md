# US-10 · Login e layout do painel

> Spec de produto para autenticação e estrutura visual inicial do painel definido no Backlog v2.

- **Épico:** Painel
- **Prioridade / pontos:** Alta · 3
- **Requisitos da spec geral:** RF-07, RNF-01, RNF-05
- **Depende de:** US-02 (schema/RLS Supabase); configuração externa de Supabase para execução autenticada

## História
Como **operador**, quero entrar com meu e-mail e senha e acessar uma interface de monitoramento responsiva, para que somente usuários autenticados vejam o painel.

## Critérios de aceite
```gherkin
Cenário: visitante tenta acessar uma rota protegida
  Dado que não há sessão Supabase válida
  Quando o visitante solicita /
  Então é redirecionado para /login

Cenário: operador autentica
  Dado que o operador informa credenciais válidas
  Quando o Supabase confirma a sessão
  Então a sessão é gravada em cookies SSR e o operador segue para /

Cenário: credenciais inválidas
  Dado que o operador informa credenciais inválidas
  Quando o Supabase rejeita o login
  Então uma mensagem acessível é exibida e nenhuma rota protegida é aberta

Cenário: operador encerra sessão
  Dado que existe uma sessão autenticada
  Quando o operador seleciona sair
  Então a sessão é encerrada e o navegador retorna a /login
```

## Casos de borda
- [x] Erro de configuração ou indisponibilidade do Supabase é informado sem revelar detalhes internos.
- [x] Sem credenciais de ambiente, a tela não finge autenticação nem usa dados demonstrativos.
- [x] Layout mantém navegação utilizável em telas estreitas e com redução de movimento.

## Fora do escopo desta história
- Dados reais de serviços, alertas, Realtime e dashboards (US-11/US-12).
- Provisionar contas de usuário ou configurar projeto Supabase/Vercel externo.

## Dados e contratos afetados
- Tabelas: nenhuma consultada pela UI nesta história.
- Métricas: nenhuma.
- Rotas: `/login`, `/` e grupo de rotas protegidas `(dash)`.
- Variáveis públicas: `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY` (aceita também chave publishable atual).

## Segurança
- O cliente usa somente URL e chave pública do Supabase; não há service-role no painel.
- A sessão é validada no servidor via Supabase SSR; as rotas do grupo `(dash)` são protegidas pelo middleware.
- E-mail e senha são enviados ao Supabase por HTTPS e nunca registrados pela aplicação.
